# Jadhav Nivaas / editable home

**Concept only, not for construction or structural approval.** Modelled from the three supplied sketches in FreeCAD BIM 1.1.4. FreeCAD remains the architectural master; the furnished Three.js scene is a visualization of that same export, not a second independently authored floor plan.

## Open and update

- Open `output\Home.FCStd` in FreeCAD. The portable application is `tools\FreeCAD_1.1.4-Windows-x86_64-py311\FreeCAD.exe`.

- The source of truth for regeneration is JSON plus `build_home.py`. The document's Parameters spreadsheet is a reference snapshot, **not live-linked**. Direct FreeCAD edits persist when saved but will be replaced by regeneration.
- Native Arch walls have editable Width/Height and Draft baselines. Doors/windows have constrained native sketches, host references and editable opening properties. Spaces are native Arch spaces. Slab, plinth and roof panels are solid Arch components with IFC classifications; their overall shape is regenerated by source, not a fully constrained roof-feature solver. Expand the Roof group and press Space to hide/show it.
- Keep rear service grid widths summing to `center_bay`. The equal-pitch monitor roof also requires `(exterior_width - monitor_width) == (exterior_depth - monitor_depth)`. Generation fails explicitly if these constraints are violated.
- Change opening **locations** in the clearly named calls to `opening()` in `build_home.py`; these use feet from the front-left outside origin. Dimensions/counts are centralized under `opening_types`.
- Run `.\Preview.ps1` and open `http://127.0.0.1:8765/` for the local Three.js viewer. If a preview is already running on that port, reuse it rather than starting another. ## Deploy on Vercel

Import [anoop-jadhav-ui/HomeModel](https://github.com/anoop-jadhav-ui/HomeModel) from the **repository root**, not the `output` subfolder. The root `vercel.json` selects a static deployment and publishes the committed `output` folder. No FreeCAD, Python server, environment variables, dependency installation or model regeneration is needed in Vercel. All Three.js runtime files are already committed.

| Vercel setting | Exact value |
|---|---|
| Root Directory | Leave blank / repository root (not `output`) |
| Framework Preset | Other (`framework: null` in configuration) |
| Build Command | `npm run build` (from configuration) |
| Output Directory | `output` (from configuration, not `.`) |
| Install Command | Empty / skipped (`installCommand: ""` in configuration) |
| Production Branch | `master`, if deploying the current repository branch |

For an existing failed project, clear its old **Root Directory** value and disable dashboard Build/Output/Install overrides so the root configuration is used. Remove any earlier catch-all SPA rewrite to `index.html`; missing JavaScript/assets must return 404, never an HTML fallback. Redeploy a revision that contains `vercel.json`, `validate-deployment.mjs` and the updated `package.json`; redeploying the old checkpoint alone cannot apply these changes. File-based commands override dashboard commands, but only when Vercel is pointed at the repository root.

`npm run build` uses only Node's built-in modules. It verifies required files, case-sensitive relative links and the complete local module/import-map graph, then leaves `output` unchanged. The configured JavaScript MIME type supports ES modules; native CAD/IFC responses are downloads. The deployed home is `/`, the plan is `/plan.html`, and the coordination package is `/Preliminary-coordination.html` (not `/output/...`). No SPA router, serverless function or long-running process is required. The scene and layout remain unchanged.

The precise cause of any earlier remote failure requires that deployment's URL or build log; these settings do not assert that a live Vercel deployment has been created or tested.

## Validation and files

The generator checks nonempty, valid positive-volume BIM objects; opening counts; expected front-wall cut volume; and room dimensions. IFC is reopened with IfcOpenShell and every represented product is converted back to geometry. `validation.json` records actual results. This verifies file/geometry integrity, **not** engineering adequacy, clash-free assemblies or regulatory compliance.

The IFC export also normalizes door/window `OverallWidth` and `OverallHeight` to the file's declared units and explicitly links the filling elements to their wall voids; the bundled FreeCAD exporter does not consistently emit those metadata correctly. Geometry remains exported from the native solids.

Run `tools\FreeCAD_1.1.4-Windows-x86_64-py311\bin\python.exe validate_saved.py` to reopen saved native/IFC files and check room/slab dimensions, nine door positions/sizes/hosts and leaf metadata, 27 host probes, the full-height 16-ft hall/dining connection, eight monitor enclosure components and all six actual 1.5 x 2-ft vent extents. Results are in `output\saved-file-validation.json`. Run `npm run validate` for furnishing solidity/fit/swing checks, and `node --test navigation.test.mjs wall-sections.test.mjs site.test.mjs validate-deployment.test.mjs` for navigation, caps/leaf thickness, site clearance/budget and clean static deployment checks.
