# Editable sketch home

**Concept only, not for construction or structural approval.** Modelled from the three supplied sketches in FreeCAD BIM 1.1.4. FreeCAD remains the architectural master; the furnished Three.js scene is a visualization of that same export, not a second independently authored floor plan.

## Open and update

- Open `output\Home.FCStd` in FreeCAD. The portable application is `tools\FreeCAD_1.1.4-Windows-x86_64-py311\FreeCAD.exe`.
- Edit `parameters.json` for coordinated changes; values are feet except roof pitch in degrees. Run `.\Regenerate.ps1` from PowerShell, or open and execute `BuildHome.FCMacro` in FreeCAD. Outputs are overwritten; copy any version you want to retain first.
- The source of truth for regeneration is JSON plus `build_home.py`. The document's Parameters spreadsheet is a reference snapshot, **not live-linked**. Direct FreeCAD edits persist when saved but will be replaced by regeneration.
- Native Arch walls have editable Width/Height and Draft baselines. Doors/windows have constrained native sketches, host references and editable opening properties. Spaces are native Arch spaces. Slab, plinth and roof panels are solid Arch components with IFC classifications; their overall shape is regenerated by source, not a fully constrained roof-feature solver. Expand the Roof group and press Space to hide/show it.
- Keep rear service grid widths summing to `center_bay`. The equal-pitch monitor roof also requires `(exterior_width - monitor_width) == (exterior_depth - monitor_depth)`. Generation fails explicitly if these constraints are violated.
- Change opening **locations** in the clearly named calls to `opening()` in `build_home.py`; these use feet from the front-left outside origin. Dimensions/counts are centralized under `opening_types`.
- Run `.\Preview.ps1` and open `http://127.0.0.1:8765/` for the local Three.js viewer. If a preview is already running on that port, reuse it rather than starting another. ES modules require HTTP: do not open the main Three.js page using a `file://` URL. All runtime libraries and assets are local; no CDN or internet is needed after download.
- Exterior: drag to orbit, scroll to zoom, right-drag to pan. Furnished cutaway hides the roof and visually clips the upper walls only. Interior/walk: drag to look, W/A/S/D or arrow keys to move; Shift slows movement; use the room selector to jump. It is not a collision/egress simulation. `Open doors*` animates explicitly assumed handing. The furniture toggle does not change the CAD master.
- Architectural plan is a **real +4-ft wall cut**, not an overhead view through opaque lintels: nine door gaps/leaves/assumed dashed swing arcs, 11 window symbols, six dashed high-level vent symbols, OPEN passages and provisional dimensions are shown. `output\plan.html` is the retained lightweight review/fallback page. In FreeCAD, execute `TogglePlan.FCMacro` to switch between the native cut-plan group and the 3D model.
- Three.js scene/update source: `output\scene.js`, `output\furnishings.js`, `output\review-data.js`, `output\plan.html` and the vendored `output\vendor` folder. Beds/mattresses/pillows/nightstands, wardrobes, toilets, washbasins/showers, kitchen cabinetry/appliances, dining furniture and living furniture are procedurally authored illustrative assets. Adjust room-relative placements in `furnishings.js`; do not change building geometry there.
- For JavaScript authoring/validation, run `npm ci`, `npm run vendor` if vendored libraries need rebuilding, then `npm run validate`. This checks actual furnishing mesh bounds, room fit, assumed door-sweep sectors and same-room hard-asset overlaps; see `output\furnishing-validation.json`. These are **not** code/accessibility/fixture-use clearance checks.
- Preliminary coordination package: `output\Preliminary-coordination.html`, printable vector `output\architectural-plan.svg`, and `output\opening-schedule.csv`. These are regenerated by `export_plan.py` from the native export. They remain **NOT FOR CONSTRUCTION**, not certified/permit-ready. Ground floor only; no engineering documents supplied; location/jurisdiction deferred.
- Exchange file: `output\Home.ifc`. Review images: `output\exterior.png`, `output\plan-cutaway.png`. Geometry/export evidence: `output\validation.json`.

## Validation and files

The generator checks nonempty, valid positive-volume BIM objects; opening counts; expected front-wall cut volume; and room dimensions. IFC is reopened with IfcOpenShell and every represented product is converted back to geometry. `validation.json` records actual results. This verifies file/geometry integrity, **not** engineering adequacy, clash-free assemblies or regulatory compliance.

The IFC export also normalizes door/window `OverallWidth` and `OverallHeight` to the file's declared units and explicitly links the filling elements to their wall voids; the bundled FreeCAD exporter does not consistently emit those metadata correctly. Geometry remains exported from the native solids.

Run `tools\FreeCAD_1.1.4-Windows-x86_64-py311\bin\python.exe validate_saved.py` for an independent reopen of the saved native model, actual room/slab dimensions, all nine door positions/sizes/hosts, 27 host-wall clearance probes, closure of the four old D1 holes, the full prayer opening and IFC door/void geometry checks. Its results are in `output\saved-file-validation.json`.

The official portable FreeCAD archive was checksum-verified against its release SHA256. The application remains local under `tools`; it is not installed system-wide. This folder has a local Git checkpoint; no remote repository, push or PR is set up.
